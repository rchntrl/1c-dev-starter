# Каталог сборки

В этой папке находятся сценарии сборки и локальные данные, необходимые для
создания артефактов 1С:

- `build-cf.ps1` и `build-cf.bat` — сборка `.cf` из XML-выгрузки в `conf`;
- `build-cfe.ps1` и `build-cfe.bat` — сборка `.cfe` из исходников в `extensions`;
- `build-ep.ps1` и `build-ep.bat` — сборка `.epf` из XML-выгрузки в `external`;
- `parameters.example.yml` — пример локальных параметров пользователя,
  платформы и значений сборки по умолчанию для PowerShell-сценариев;
- `ib` — локальная файловая информационная база, используемая при сборке;
- `logs` — журналы запуска Designer для диагностики ошибок. Консольный вывод
  Designer для PowerShell-сценариев сохраняется в отдельные файлы `*-console.log`.

Информационная база, журналы и резервные файлы игнорируются Git. README и
сценарии сборки хранятся в репозитории. У каждого сценария есть вариант `.ps1`
и `.bat`; оба варианта принимают одинаковые аргументы и собирают те же артефакты.
Примеры ниже показывают оба способа запуска из корня репозитория.

Для сборки конфигурации:

```powershell
.\.build\build-cf.ps1 [имя-конфигурации] [версия-платформы]
.\.build\build-cf.bat [имя-конфигурации] [версия-платформы]
```

Например, `.\.build\build-cf.ps1 1Cv8 8.3.24.1691` или
`.\.build\build-cf.bat 1Cv8 8.3.24.1691` создаст `1Cv8.cf` в корне проекта.
По умолчанию используются имя `1Cv8` и платформа `8.3.24.1691`.

Для сборки расширения:

```powershell
.\.build\build-cfe.ps1 [имя-расширения] [версия-платформы]
.\.build\build-cfe.bat [имя-расширения] [версия-платформы]
```

По умолчанию используется расширение `GS` и платформа `8.3.24.1691`. Например,
для сборки `GS` на платформе `8.3.24.1691` передайте `GS 8.3.24.1691` любому
из сценариев.

Для сборки внешней обработки (имя XML обязательно):

```powershell
.\.build\build-ep.ps1 <имя-обработки> [версия-платформы]
.\.build\build-ep.bat <имя-обработки> [версия-платформы]
```

Корневой XML-файл обработки должен находиться в `external` и называться
`<имя-обработки>.xml`. Результат будет сохранён в корне проекта как
`<имя-обработки>_ГГГГ-ММ-ДД.epf`. Версия платформы по умолчанию — `8.3.24.1691`.
Если Designer вернул ненулевой код, PowerShell-сценарий всё равно считает сборку
успешной только когда его журнал содержит сообщение об успешном завершении,
указанный в свежем журнале целевой путь совпадает с ожидаемым, а файл `.epf`
создан или обновлён во время текущей сборки. После запуска Designer сценарий
ожидает подтверждения в журнале и файле до 60 секунд.

Если политика выполнения PowerShell блокирует локальный `.ps1`, можно запустить
его в отдельном процессе с `-ExecutionPolicy Bypass`, например:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .build\build-ep.ps1 MyProcessor
```

Это задаёт политику только для запущенного процесса и не меняет системные
настройки.

### Вход в инфобазу с пользователем

PowerShell-сценарии читают необязательные настройки из
`.build\parameters.yml`. Скопируйте `.build\parameters.example.yml` в
`.build\parameters.yml` и задайте нужные значения:

```yaml
username: "Администратор"
password: "ВашПароль"
platform: "8.3.24.1691"
configuration: "1Cv8"
extension: "GS"
```

Файл `parameters.yml` исключён из Git. Если он отсутствует, сохраняются прежние
значения по умолчанию: платформа `8.3.24.1691`, конфигурация `1Cv8` и расширение
`GS`. Значения конфигурации и расширения используются только для соответствующих
сценариев. Аргументы командной строки имеют приоритет над `platform`,
`configuration` и `extension` из файла.

Если имя пользователя и пароль не заданы, Designer запускается без `/N` и `/P`.
Если задано только одно из двух значений, сценарий завершится с ошибкой.
Создание новой пустой инфобазы выполняется без этих параметров; они добавляются
только для команд Designer, работающих с инфобазой. Для `.bat`-вариантов YAML
настройки не применяются, и логин с паролем Designer не передаются. Поэтому
`.bat`-варианты рассчитаны на пустую файловую инфобазу без пользователей.
Для работы с инфобазой, где настроены пользователи, используйте `.ps1`-сценарии
и задайте `username` и `password` в `.build\parameters.yml`.

Пароль, переданный Designer параметром `/P`, может быть виден в командной
строке процесса.

Учтите, что пароль, переданный через `/P`, доступен в аргументах запущенного
процесса 1С.
