# Стиль кода BSL

Опирается на стандарты 1С (its.1c.ru/db/v8std) и на фактический стиль прикладного кода конфигурации.

## Форматирование

- Кодировка UTF-8 **с BOM**, переводы строк CRLF, отступ — **табуляция**.
- Ключевые слова — в русском варианте, с заглавной: `Если ... Тогда`, `Для Каждого ... Из ... Цикл`,
  `КонецЦикла`, `Истина/Ложь` (не `TRUE/FALSE`, не `цикл` в нижнем регистре).
- Пустая строка после заголовка процедуры и перед `КонецПроцедуры/КонецФункции` — как в существующем коде.
- Длинные вызовы с многими параметрами переносить построчно, по одному параметру.
- Не оставлять закомментированный «мёртвый» код и отладочные `Сообщить()`.

## Структура модуля

Использовать стандартные области (`#Область ... #КонецОбласти`, в новом коде — русский вариант):

- Общие модули: `ПрограммныйИнтерфейс`, `СлужебныйПрограммныйИнтерфейс`, `СлужебныеПроцедурыИФункции`.
- Модуль объекта/менеджера: `ПрограммныйИнтерфейс`, `ОбработчикиСобытий`, `СлужебныеПроцедурыИФункции`.
- Модуль формы: `ОбработчикиСобытийФормы`, `ОбработчикиСобытийЭлементовШапкиФормы`,
  `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>`, `ОбработчикиКомандФормы`, `СлужебныеПроцедурыИФункции`.
- Код модулей объектов, выполняющийся на сервере, обрамлять
  `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда ... #Иначе ВызватьИсключение ... #КонецЕсли`.

## Именование

- Имена — по-русски, CamelCase, осмысленные, без сокращений (`ДатаНачала`, не `ДатаНач`; `Строка`, не `Ъ`).
- Префикс `пер`, однобуквенные и «мусорные» имена (`Ъ`, `ТЗ1`) в новом коде не использовать.
- Экспортные методы общих модулей — с комментарием-описанием по стандарту:

```bsl
// Возвращает остаток отпускных дней сотрудника на дату.
//
// Параметры:
//   Сотрудник - СправочникСсылка.Сотрудники - сотрудник.
//   Период    - Дата - дата, на которую считается остаток.
//
// Возвращаемое значение:
//   Число - остаток дней.
//
Функция ОстатокОтпускныхДней(Сотрудник, Период) Экспорт
```

## Клиент-сервер

- Минимизировать серверные вызовы с клиента: один `&НаСервере` вызов, возвращающий всё нужное.
- Предпочитать `&НаСервереБезКонтекста`, если контекст формы не нужен.
- Не обращаться через точку к реквизитам ссылок на клиенте; на сервере для чтения реквизитов по ссылке
  использовать `ОбщегоНазначения.ЗначениеРеквизитаОбъекта / ЗначенияРеквизитовОбъекта` вместо `Ссылка.Реквизит.Реквизит`.
- Модальные окна формально разрешены, но в новом коде использовать асинхронные методы
  (`ПоказатьВопрос`, `ОписаниеОповещения`, `ПоказатьПредупреждение`).
- Дата: на сервере — `ТекущаяДатаСеанса()`, не `ТекущаяДата()`.

## Запросы

- Никаких запросов в цикле — собирать данные одним запросом / через временные таблицы.
- В пользовательских сценариях — `ВЫБРАТЬ РАЗРЕШЕННЫЕ`; в привилегированном коде (HTTP-сервис, регламент) — осознанно без.
- Текст запроса оформлять многострочным литералом с `|`, псевдонимы через `КАК`, параметры через `&`.
- Для периодического РС `Сотрудники` — `СрезПоследних(&Дата, Сотрудник = &Сотрудник)` с отбором в параметрах
  виртуальной таблицы, а не в `ГДЕ`.
- Предопределённые значения в запросе — `ЗНАЧЕНИЕ(Перечисление.ТипыОтпусков.Трудовой)`;
  в коде — `Перечисления.ТипыОтпусков.Трудовой` (сервер) / `ПредопределенноеЗначение(...)` (клиент).

## Транзакции и блокировки

- Режим блокировок — управляемый: перед чтением остатков для контроля ставить `БлокировкаДанных`.
- Схема транзакции:

```bsl
НачатьТранзакцию();
Попытка
	// блокировка + чтение + запись
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(...);
	ВызватьИсключение;
КонецПопытки;
```

## Сообщения и ошибки

- Сообщения пользователю — `ОбщегоНазначения.СообщитьПользователю(Текст, Объект, Поле, , Отказ)`.
- Все строки для пользователя — `НСтр("ru = '...'; en = '...'")`, обязательно оба языка.
- В `Исключение` не глушить ошибку молча: писать в журнал регистрации
  (`ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`) и/или пробрасывать.
- Проверки заполнения — в `ОбработкаПроверкиЗаполнения` с `Отказ = Истина`, не через исключения.
