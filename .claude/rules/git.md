# Работа с Git

## Что коммитить

- `conf/` (выгрузка основной конфигурации) отслеживается в основной ветке.
- Выгрузки расширений (`extensions/<имя>/`) и внешних обработок (`external/<имя>.xml` + одноимённая папка)
  игнорируются Git (`extensions/*`, `external/*` в `.gitignore`), в основной ветке отслеживаются только
  `README.md` этих каталогов. Сами выгрузки и их история хранятся в отдельных рабочих ветках.
- В основную ветку выгрузки расширений и внешних обработок не попадают: это проверяют хук
  `.githooks/pre-push` (включается `git config core.hooksPath .githooks`) и workflow
  `.github/workflows/no-external.yml` для PR.

## Ветки расширений и внешних обработок

- Рабочая ветка называется по типу и имени выгрузки, тип — в единственном числе:
  `extensions/<имя-расширения>/` → `extension/<имя-расширения>`, `external/<имя-обработки>` → `external/<имя-обработки>`.
- Ветку создавай от основной ветки. В ней добавь в `.gitignore` исключение для своей выгрузки
  (например, `!external/<имя-обработки>*` или `!extensions/<имя-расширения>/`), чтобы она отслеживалась.
- Описание расширения или обработки пиши в рабочей ветке в `.github/README.md`, а не в README каталогов
  `extensions/` и `external/`: GitHub показывает этот файл на главной странице ветки и тега вместо
  корневого `README.md`. Ссылки в нём — относительно `.github/` (`../README.md`, `../external/<имя>`).
  README каталогов в рабочей ветке оставляй таким же, как в основной ветке.
- При переключении на рабочую ветку укажи её выгрузку в `.build/parameters.yml`: для ветки
  `external/<имя-обработки>` — `external: "<имя-обработки>"`, для ветки `extension/<имя-расширения>` —
  `extension: "<имя-расширения>"`. Остальные параметры не меняй.
- Рабочая ветка живёт отдельно от основной ветки и в неё не вливается.
- Когда работа в ветке закончена, предложи пользователю опубликовать готовый релиз аннотированным тегом
  (`git tag -a`) с именем `<ветка>/<версия>`, например `external/MyProcessor/1.0`. Без его согласия тег не создавай и ветку не удаляй.
