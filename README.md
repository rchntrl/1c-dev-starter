# ru_lcw_retail

Проект предназначен для подготовки и сборки артефактов 1С: конфигураций,
расширений конфигурации и внешних обработок. Ветка `main` содержит инструкции,
сценарии сборки, при необходимости дампы конфигурации и шаблон внешней
обработки `INTEGRATION_TOOLS_RMv2.0`. Дампы расширений и собственных внешних
обработок хранятся в отдельных ветках и публикуются только тегами.

## Правила Git

- В `main` можно добавлять одну выгрузку конфигурации, расположенную прямо в
  `conf`. Перед добавлением удалите из `.gitignore` правило `conf/*`, затем
  добавьте дамп командой `git add conf/`.
- `external/INTEGRATION_TOOLS_RMv2.0` — исключение: это общий шаблон для
  создания новых обработок, который хранится в `main`. Не используйте его
  каталог для конкретных обработок.
- Не добавляйте дампы из `extensions` и `external` в `main` и не вливайте в
  `main` ветки разработки. Это правило не относится к шаблону
  `INTEGRATION_TOOLS_RMv2.0`.
- Для изменения расширения или внешней обработки сначала создайте отдельную
  ветку от `main`. Только после переключения на неё добавляйте нужный дамп в
  Git. По умолчанию каталоги игнорируются; используйте `git add -f` для
  конкретного дампа, не снимая игнорирование со всего каталога.
- Зафиксируйте готовое состояние коммитом и создайте аннотированный тег:

  ```powershell
  git switch main
  git pull --ff-only
  git switch -c work/extension-MyExtension
  git add -f extensions/MyExtension
  git commit -m "Обновить расширение MyExtension"
  git tag -a extension-MyExtension-v1.0.0 -m "MyExtension v1.0.0"
  git push origin refs/tags/extension-MyExtension-v1.0.0
  ```

  Для внешней обработки используйте `external/<имя>` и тег вида
  `external-<имя>-v1.0.0`. Отправляйте в удалённый репозиторий тег, а не
  рабочую ветку. Ветка остаётся отдельной от `main`; при необходимости её можно
  сохранить локально для дальнейшей работы. Каждый выпуск получает новый тег.

## Каталоги

- `conf` — исходные файловые выгрузки конфигурации, которые можно версионировать
  в `main`;
- `extensions` — исходные файловые выгрузки расширений, версионируемые только
  в отдельных ветках и тегах;
- `external` — шаблон `INTEGRATION_TOOLS_RMv2.0` и исходники внешних обработок;
  шаблон хранится в `main`, остальные обработки версионируются только в
  отдельных ветках и тегах;
- `.build` — сценарии сборки, локальная информационная база и журналы.

## Сценарии сборки

- `.build/build-cf.ps1` / `.build/build-cf.bat` — сборка `.cf` из XML-выгрузки в `conf`;
- `.build/build-cfe.ps1` / `.build/build-cfe.bat` — сборка расширения из `extensions`;
- `.build/build-ep.ps1` / `.build/build-ep.bat` — сборка внешней обработки из XML-выгрузки в `external`.

### Как читать команды сборки

Оба варианта запускаются из корня репозитория. Для PowerShell используйте
`.ps1`, для командной строки Windows — `.bat`. Аргументы указываются в одном
порядке: имя исходного артефакта, затем (необязательно) версия платформы.

```powershell
.\.build\build-ep.ps1 INTEGRATION_TOOLS_RMv2.0
.\.build\build-ep.bat INTEGRATION_TOOLS_RMv2.0
```

Здесь:

- `build-ep.ps1` и `build-ep.bat` — сценарии сборки внешней обработки;
- `INTEGRATION_TOOLS_RMv2.0` — имя исходного XML-файла без расширения `.xml`;
- сценарий ищет файл `external\INTEGRATION_TOOLS_RMv2.0.xml`;
- финальный артефакт сохраняется в корне проекта как `INTEGRATION_TOOLS_RMv2.0_YYYY-MM-DD.epf`.

Для конфигурации и расширения также можно выбрать любой вариант:

```powershell
.\.build\build-cf.ps1 1Cv8 8.3.24.1691
.\.build\build-cf.bat 1Cv8 8.3.24.1691
.\.build\build-cfe.ps1 GS 8.3.24.1691
.\.build\build-cfe.bat GS 8.3.24.1691
```

Имена и версии можно передать аргументами; версии по умолчанию указаны в
сценариях.

Если политика выполнения блокирует запуск `.ps1`, используйте отдельный процесс,
например: `powershell -NoProfile -ExecutionPolicy Bypass -File .build\build-ep.ps1 INTEGRATION_TOOLS_RMv2.0`.
Это не меняет системные настройки; подробности приведены в [README каталога сборки](.build/README.md).

Подробности о назначении локальных каталогов находятся в README внутри них.
